# Context — Continue the Right Task

Use this guide when resuming, compacting, summarizing or handing off programming work. Ordinary questions with sufficient current context need no new notes or summary artifact. The entrypoint governs the active task and authorized actions.

## Recover decision-relevant context

Preserve the intended outcome, accepted constraints and explicit restrictions; the relevant decisions and why they were made; the current artifact or code locations; completed and outstanding work; verification evidence and limits; and the next uncertainty or action necessary for that task.

Keep user corrections and accepted guidance, including what changed in the interpretation. Distinguish facts, hypotheses, proposals and completed work so a successor does not turn a conditional recommendation into a settled implementation step. Preserve important ownership and compatibility guarantees when they explain the approach.

For partial or recent summaries, cover the portion being replaced without duplicating context that remains available. Include exact code, commands, errors or user wording only when the detail is necessary to continue correctly; do not reproduce the full conversation or internal analysis as a template requirement.

## Reconcile with the present

A summary or memory records what was known then. Check current files, diff, environment or available resources before relying on a mutable fact. If evidence contradicts old context, use the current observation and explain the relevant change. Do not delete or rewrite persistent memories automatically; follow the actual storage system and authorization when persistence is requested.

Match a previous plan to the current user request. Continue an unfinished relevant task, revise a superseded assumption or start from the new topic as appropriate. Do not revive completed work, silently drop accepted constraints or use an old task's authorization for a new one.

## Handoff without expanding scope

Provide enough context for a competent colleague to identify the target, understand the constraints, assess the evidence and take the next relevant step. State what is unknown rather than substituting a confident guess. Report a pending check as pending and a delegated result only after it actually arrives.

Context handoff does not require a team, transcript mining, scheduled maintenance or a memory service. Use persistent files or delegation only when the task and host permit them, with clear ownership and scope. Finish with an actionable continuation or requested summary, without adding an unrelated backlog.
